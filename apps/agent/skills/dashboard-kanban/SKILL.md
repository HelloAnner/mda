# 现代企业 Kanban 看板

## 任务与边界

Kanban 的首要任务是让用户快速看清工作分布、流动、阻塞、老化与下一步行动，而不是展示一组漂亮卡片。先确认：

- 每张卡代表什么业务实体，卡片数量和排序意味着什么。
- 每条泳道代表真实流程状态、责任范围还是其他分组；不要把普通分类伪装成流程。
- 进入、离开和阻塞状态的业务定义，以及完成、取消、未知和陈旧数据如何处理。
- WIP 限制、服务等级、截止时间、优先级和升级规则是否真实存在。
- 看板是只读观察面，还是平台确实提供可持久化的状态变更。MDA 数据上下文默认只读；没有真实写入能力时不得提供可拖拽手柄、虚假成功反馈或暗示卡片已被移动。

## 信息密度与扫描顺序

使用高效但不拥挤的组件层级。密度来自信息取舍、稳定对齐和紧凑节奏，而不是缩小到难以阅读。

- 顶部使用克制的工具区承载范围、搜索、筛选、排序、刷新时间，以及真实存在的总量、进行中、阻塞、逾期或吞吐摘要；不要再叠一层大型 KPI 卡墙。
- 泳道标题应同时交代状态名称、对象数量，并在有依据时显示 WIP 限制、老化或风险摘要。标题在滚动时保持上下文。
- 卡片第一层只保留识别与行动所需信息：清晰标题、关键业务对象或编号、优先级/风险、负责人、截止或老化、阻塞原因，以及最多一个关键数值。字段缺失要诚实显示，不用装饰补位。
- 卡片第二层细节通过展开、侧栏或详情视图进入；首屏不重复描述泳道已经表达的状态。
- 使用一致的元数据顺序、图标位置、数字格式和标签宽度，让用户能纵向扫读。标题通常限制在两行，并提供不依赖 hover 的完整查看路径。
- 在流程真实包含这些阶段时，典型桌面首屏应尽量同时看清主要 4–6 条泳道和每条泳道中的多张真实内容卡片；不要为了达到数量而制造泳道，也不要用巨大留白让一屏只能看到一两张卡。
- 标签、头像、徽章和图标必须携带信息。合并低价值标签，避免每个字段都变成彩色胶囊。

## 现代企业组件化视觉

采用精确、模块化、可信的企业工作台气质，而不是营销落地页或游戏化任务板。

- 使用冷静的中性页面底色、清晰的浅色表面、细描边、克制的小圆角和极弱或无阴影。用一处品牌强调色建立焦点，状态色只表达真实语义。
- 组件语言保持一致：工具栏、泳道头、卡片、标签、头像、图标按钮和详情面板共享统一的间距、边框、字体和交互状态，但不要求固定组件库、代码结构或网格 Schema。
- 标题、正文、元数据和数字形成明确的四级以内层级。数字需要时使用等宽或表格数字；辅助信息降低对比度但仍满足可读性。
- 通过 1px 边界、轻微表面层次、精确对齐和细腻 hover/focus 状态体现现代感。动画短促并服务于位置、选择或展开理解；尊重 reduced motion。
- 只保留一处克制的标志性细节，例如精确的老化刻度、流程进度线或品牌化选中态。它必须编码真实信息，而不是装饰。

避免用玻璃拟态、霓虹、发光、浓重渐变、彩虹泳道、巨大圆角和漂浮阴影制造“现代感”。企业感来自秩序、材料精度和可信信息，不是模板化蓝色卡片。

## 交互

- 搜索、负责人、优先级、标签、日期和状态筛选只在支持真实任务时出现；当前范围和清除方式始终可见。
- 默认排序必须可解释，例如优先级后按老化、截止时间或明确队列顺序。不要在自动刷新时悄悄重排用户正在阅读的卡片。
- 卡片选择应有明确选中态，并保留横向滚动、泳道位置、筛选和焦点。关闭详情后返回原卡片。
- 若真实支持移动，明确允许的转换、失败回滚、并发冲突和保存状态，并提供键盘等价操作。拖拽不能成为唯一入口。
- 泳道折叠、密度切换或批量动作仅在真实需求和能力存在时加入；不要用控件数量伪装专业性。

## 响应式行为

- 桌面端保持稳定泳道宽度。阶段较多时使用边界清楚、可发现的局部横向滚动；页面本身不应产生意外溢出。泳道头在局部滚动中保持可见。
- 中等宽度可以减少同时显示的泳道，但不能把卡片压到字段不可读。
- 移动端优先采用单泳道切换或按状态分组的紧凑列表，并保留数量、筛选和当前位置；不要把完整桌面板机械缩成数列窄卡。
- 触控目标、键盘顺序和焦点边界清楚；颜色不是状态、优先级或阻塞的唯一载体。

## 状态与真实性

- 加载骨架应保留工具区和泳道结构，避免数据到达后整体跳动。
- 区分整个看板为空、某泳道为空、筛选无匹配、部分泳道失败、数据陈旧、刷新中、无权限和未知状态。
- 空泳道保持紧凑，不用巨型插画撑高页面；解释该状态是否正常以及用户可采取的真实行动。
- 刷新失败时保留最后成功数据与时间，并明确哪些数量或卡片可能已过期。
- WIP、逾期、老化和阻塞必须来自真实字段与规则；不要根据卡片颜色或位置臆造。

## 避免

不要使用巨大页头、重复 KPI 卡、低密度大卡、每列不同底色、满屏彩色标签、无意义头像、只靠 hover 的细节、无限高泳道、隐藏滚动条或假拖拽。不要让“组件化”退化成边框套边框，也不要为了企业感牺牲长标题、键盘路径和异常状态。

## 质量门

用真实长度的标题、缺失负责人、逾期、阻塞、空泳道、30 张以上卡片和 5–7 个阶段进行压力检查：

- 用户能否在十秒内找到最拥堵、最老、已阻塞和最需要行动的对象？
- 不打开详情时，是否已有足够信息区分并排序卡片？打开详情后能否准确返回？
- 首屏密度是否足以形成流程全局感，同时仍能舒适阅读？
- 横向和纵向滚动是否局部、可预期，并保留泳道与筛选上下文？
- 只读看板是否完全没有虚假变更暗示？若支持移动，键盘、失败和冲突路径是否完整？
- 视觉是否像精心打磨的现代企业产品，而不是通用卡片模板或装饰性原型？
