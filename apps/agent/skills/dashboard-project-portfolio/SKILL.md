# 项目与项目组合看板 Know-how

## 核心决定

帮助发起人和交付团队判断组合是否仍与战略一致、哪些项目需要干预、依赖和资源如何影响承诺、收益是否真正实现。

## 指标关系

- 范围与进度：基线、当前计划、完成、预测完工和关键里程碑。
- 成本：批准预算、实际、承诺、剩余预测和完工估算，口径一致。
- 风险：概率、影响、趋势、所有者、缓解和到期；风险数量不是风险水平。
- 依赖：上游/下游、关键路径、阻塞时长和跨项目影响。
- 资源：需求、容量、关键技能和冲突；利用率高不等于交付健康。
- 收益：计划收益、实现时间、实际证据和责任人，不在上线时自动宣告完成。

## 信息组织

组合视图先看战略、价值、风险和容量，再进入项目。项目视图先看承诺变化、关键路径和行动。状态必须能追到证据，不能由主观红黄绿替代。

## 视觉与交互

时间轴、网络、表格或自定义视图均可；选择最能解释依赖和偏差的形式。保持基线与最新预测并列，突出变化而非静态计划。

## 状态

区分未开始、进行、阻塞、暂停、取消、完成和未知；显示报告日期与更新责任。很久未更新的绿色项目应表现为陈旧，而非健康。

## 避免

不要用完成百分比制造虚假精确，不以任务数量衡量价值，不把所有项目压成一排状态灯，不隐藏基线重设。

## 质量门

管理者能否识别需要决定的项目、其影响与证据？基线、预测、风险、依赖、资源和收益是否形成一致故事？
