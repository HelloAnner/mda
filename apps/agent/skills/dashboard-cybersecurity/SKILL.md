# 网络安全看板 Know-how

## 核心决定

帮助安全与业务负责人理解哪些风险需要优先、事件影响什么、检测与响应是否有效、控制缺口如何变化。NIST CSF 强调高层安全结果与风险沟通，而不是规定实现方式；看板也应关注结果而非工具数量。

## 指标关系

- 风险：威胁、暴露、资产关键性、业务影响与控制状态共同决定优先级。
- 资产：覆盖、所有者、互联网暴露、未知资产和数据新鲜度。
- 漏洞：可利用性、暴露、年龄、补丁可用、例外与 SLA；严重度分数不能单独排序。
- 检测：信号量、误报、覆盖、滞留和检测时间。
- 响应：确认、遏制、恢复、复盘与未结行动，保留事件时间线。
- 身份：高权限、异常活动、多因素覆盖和访问审查（在合法授权范围内）。

## 信息组织

运营视图先显示正在发生的事件与影响；风险视图先显示趋势、关键暴露与治理缺口。允许从风险聚合进入资产或证据，但最小化敏感技术细节和攻击面泄露。

## 视觉与状态

严肃、清楚、低噪声。不要默认黑底霓虹。颜色表示经过定义的严重性与处置状态；未知、未覆盖、数据源离线不能呈现为安全。时间、时区和最后采集持续可见。

## 避免

不要用攻击次数制造恐慌，不用漏洞总数评价安全，不将日志量当检测质量，不用合规通过替代实际风险，不暴露凭据、利用步骤或敏感资产详情。

## 质量门

用户能否解释优先级为何成立、影响哪些关键资产、当前处置状态和证据新鲜度？未知覆盖是否会被误解为没有风险？
