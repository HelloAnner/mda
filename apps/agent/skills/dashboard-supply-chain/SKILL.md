# 供应链看板 Know-how

## 核心决定

帮助计划、采购和运营团队在服务水平、库存、成本、速度与韧性之间做权衡。单点最优可能损害整条链路，因此优先呈现端到端关系。

## 指标关系

- 需求与计划：预测偏差、偏差方向、需求变化和计划稳定性。
- 供应与采购：供应商交付、提前期、质量、价格差异和集中风险。
- 库存：可用、在途、预留、呆滞、缺货、周转和覆盖天数。
- 履约：订单周期、按时足量（口径明确）、积压、拆单与取消。
- 物流：节点、在途时间、异常、运费和损坏。
- 退货：原因、恢复价值、处置周期与质量反馈。

指标需按 SKU、地点、供应商、客户等级和时间分层，同时防止高销量聚合淹没关键长尾。服务率上升可能由过量库存换取，成本下降也可能增加风险。

## 视觉与交互

从服务与风险摘要进入流程阶段、节点和对象。地图只在空间路线影响决定时使用。流量或网络表达要保持方向、数量和瓶颈可读。

## 状态

显示数据截止、在途延迟、计划版本、未确认订单、主数据缺失和估算库存。未知 ETA 不能当作准时。

## 避免

不要只看平均提前期，不把预测准确率脱离偏差方向，不用库存总额掩盖缺货与呆滞并存，不把供应商排名脱离品类难度。

## 质量门

用户能否看见服务、库存、成本和风险的权衡，并沿链路定位真正约束而非局部症状？
