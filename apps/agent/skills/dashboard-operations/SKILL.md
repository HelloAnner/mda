# 运营与指挥看板

## 决策任务

帮助用户迅速回答：现在是否健康、哪里异常、影响多大、何时开始、谁在处理、下一步看哪里。可浏览性与处置速度优先于装饰。

## 信息组织

- 先呈现整体状态和真正需要行动的异常，再呈现系统、区域或流程分解。
- 正常、退化、阻塞、未知和维护状态必须区分；未知不能显示成正常。
- 把吞吐、延迟、错误、积压、容量与业务影响联系起来，不只展示资源百分比。
- 事件时间线保留开始、确认、缓解、恢复和关联变化。
- 告警应能导向相关证据或处置上下文；不要让用户无目的浏览。

## 视觉气质

密度可以高，但层级必须稳定。中性背景承载大部分信息，告警色只用于需要行动的少数状态。使用准确时间、紧凑但可读的行距、清楚的分组与强对齐。避免“赛博控制室”霓虹装饰。

## 刷新与交互

- 显示最后成功刷新、刷新频率、暂停状态和数据延迟。
- 自动刷新不得打断选择、滚动、键盘焦点或正在查看的事件。
- 保留旧数据并标记陈旧，通常优于清空整个页面。
- 支持按影响、状态、区域或责任范围聚焦，并让当前筛选始终可见。
- 窄屏优先异常摘要与行动信息，细节按需进入。

## 状态语义

阈值应来自目标或运行基线，而不是为了填充颜色。区分症状与原因、告警与事件、瞬时尖峰与持续退化、总量与速率。聚合不能淹没小规模但高严重度对象。

## 避免

不要让每个指标都闪烁，不用红色表示普通高值，不把几十个折线挤在同一坐标，不用绿色海洋证明“正常”，不隐藏无数据或采集失败。

## 质量门

模拟凌晨值班：十秒内能否找到最重要异常及影响？刷新失败、部分数据、长队列和多事件同时发生时，页面是否仍然可读和可操作？
