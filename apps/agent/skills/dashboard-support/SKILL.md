# 客户支持看板 Know-how

## 核心决定

帮助管理者和服务团队平衡速度、质量、负荷与客户影响：哪里积压、哪些客户在等待、SLA 为何失守、哪些问题反复出现。

## 指标关系

- 需求：新建量、渠道、主题、客户层级和突发事件。
- 队列：开放积压、年龄分布、优先级、未分配和临近 SLA。
- 速度：首次响应、下一响应、解决时间；同时看中位数与尾部。
- 质量：一次解决、重开、转派、升级、质检和满意度。
- 产能：在岗、处理量、占用与班次；不要用产量单独评价个人。
- 客户影响：受影响客户、关键账户、等待时长与重复联系。

## 口径

明确工作时间或自然时间、暂停状态、机器人与人工、已解决与已关闭、SLA 适用范围。积压总数必须结合年龄和优先级，平均响应不能掩盖长尾。

## 视觉与操作

先呈现需要行动的队列和客户影响，再显示趋势与根因。允许从主题或渠道进入具体工单（权限允许时），并保持敏感内容最小化。

## 状态

数据延迟、工单同步失败、SLA 规则变化和满意度低回收率要显式。空队列是良好状态还是数据中断需可区分。

## 避免

不要以彩色排行榜制造速度竞赛，不以满意度均值掩盖样本量，不把自动关闭当作解决，不忽略转派和重开造成的客户成本。

## 质量门

用户能否识别最需要处理的积压、其客户影响与可能原因，同时避免用单一速度指标牺牲质量？
